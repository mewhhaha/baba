# Limits

Status: current compiler and runtime limit guide.

Baba uses limits in two phases: compiler planning limits during generation, and
runtime limits in generated parsers.

## Compiler Limits

Compiler limits bound grammar and regex analysis before explosive intermediate
structures can dominate a compile. They include regex source length, regex AST
size and nesting, bounded-repeat expansion, NFA/DFA states, overlap work,
grammar expression depth, LR closure work, parser states, parser items, parser
table entries, and generated bytes.

Nested regex groups default to 256 levels. Nested EBNF source grouping defaults
to a parser guard of 256 levels, and analyzed-grammar traversal defaults to
1,024 expression nodes. Use `--regex-nesting-limit`,
`--grammar-expression-depth-limit`, or the matching target option to lower the
analysis limit for stricter adversarial-input budgets.

Limit failures are deterministic structured diagnostics. The compiler should not
rely on JavaScript stack overflow, out-of-memory failures, or generic exceptions
for expected exhaustion.

## Target Limits

Portable runtime planning limits apply to the generated Wasm parser plan.
Generated-size limits cover the emitted Wasm bundle artifacts.

## Runtime Limits

Generated parser options can bound ambiguity and trace work:

- `maxExploredBranches`;
- `maxQueuedBranches`;
- `maxTraceActions`.

Exhaustion reports structured parser diagnostics such as `PARSER_BRANCH_LIMIT`
or `PARSER_TRACE_LIMIT`.

Generated Wasm parser instances also accept `ParserInstanceLimits` through
`createParser({ limits })`, `createParserAsync({ limits })`, and the low-level
Wasm factory functions. The adapter enforces bounds for input UTF-16 units,
token capacity/count, parser stack capacity, requested branch and trace
ceilings, copied branch-cell budget, public CST node/child materialization,
lex/parse diagnostics, and Wasm memory pages. These failures throw
`WasmResourceLimitError` with stable codes: `INPUT_LIMIT_EXCEEDED`,
`TOKEN_LIMIT_EXCEEDED`, `PARSER_STACK_LIMIT_EXCEEDED`,
`PARSER_BRANCH_LIMIT_EXCEEDED`, `TRACE_LIMIT_EXCEEDED`,
`CST_NODE_LIMIT_EXCEEDED`, `DIAGNOSTIC_LIMIT_EXCEEDED`, or
`MEMORY_LIMIT_EXCEEDED`.

## Size Budgets

`deno task size:report` measures repository bytes, publish payload bytes, local
generated example bytes, duplicate generated bytes, largest files, and Wasm
binary versus embedded TypeScript representation where both exist.

`deno task size:check` evaluates `size-budgets.json` and is part of CI.
