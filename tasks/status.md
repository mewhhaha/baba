## P0.1 Runtime Source-Of-Truth Audit

Intentional host boundaries and larger runtime-lowering work still outside the
completed closure cards:

- Generated TypeScript lexer and parser wrappers still own the JavaScript
  `SourceTextBoundary`, source slicing/matching capability reads, and code-unit
  reads, while runtime-language `sourceText*` helpers now own source offset
  status, span status, trail-unit availability, UTF-16 code-point decoding, next
  offset calculation, accepted candidate-end arithmetic, public token class
  selection, and preserve-trivia emission status.
- Generated parser adapters still map public token object strings, channels,
  literals, spans, EOF records, and plan-local terminal hints into runtime
  numeric token records at the API boundary; runtime-language helpers own the
  executable token-stream classification and compacted-stream public-index
  sentinel.
- Generated parser adapters still compact public token streams into trace input
  vectors, validate host-owned source text against public token spans, and
  select public token-stream diagnostics/messages after runtime status helpers
  classify the numeric cases.
- Generated TypeScript replay still iterates accepted parser-trace actions and
  dispatches host object allocation, while runtime-language helpers provide
  action/reduction/field/fragment classification, accepted-root classification,
  and arithmetic.
- Public CST, token, field, diagnostic, and parse-result JavaScript object
  allocation remains host-owned through shared runtime-target materializers.
- Expected/found display strings and human-readable diagnostic message text
  remain host-owned, with runtime-language helpers providing stable runtime
  codes, code-status checks, detail-kind IDs, spans, and numeric payloads.
- Generated Wasm JavaScript adapters still own host source-buffer capabilities,
  linear-memory source writes, result-buffer lifetimes, and public object
  wrapping around the core Wasm/runtime-language records.
